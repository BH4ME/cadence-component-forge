# v0.48.0 — Faster previews and automatic library paths

发布日期：2026-11-11。Windows x64，MIT 开源。

## 修复内容

- **找不到已生成的封装**：打开插件、切换元件库及完成导入时，使用 Capture 原生接口登记封装路径，并为 Allegro 登记 `psmpath`、`padpath`、`steppath`。保留已有设置，修改前备份环境文件；登记失败在面板提示。已经运行的 Allegro 需要重新启动以读取环境文件。
- **CEF 面板点击元件等待太久**：先显示原始符号、封装的二维预览，点击“加载 3D”再下载原始 STEP 并生成显示网格。完整资源导入仍处理 STEP。新增可复用的二维/三维准备缓存，校验源数据、转换版本、Cadence 目标及文件完整性。
- **CEF 面板切换元件卡住**：预览期间允许继续选择，只保留最新排队请求，忽略过期响应。导入和放置不会被切换操作中断。
- **后台启动**：所有搜索入口统一选择 `pythonw.exe`；裸 `python`/`python3` 路径也会解析到对应的无窗口运行时。缺少 `pythonw.exe` 时明确提示修复安装，不回退到控制台程序。
- **三维服务退出**：本地外部预览服务不可用时，自动回退到安装包中的 STEP 渲染器。
- 安装包包含此前已在源码修复的 **JLC/LCSC 两项菜单变灰** 问题。磁盘空间不足时提前报告。

转换继续使用供应方原始符号、封装及 STEP；没有 CAD、缺少 STEP、无法忠实转换的异形结构等状态会明确报告。

## 性能实测

以下来自同一台 Windows 电脑。前四项为独立 worker 耗时，包含 Python 启动、不包含 Capture 界面绘制；后三项为后端函数耗时，不含进程启动。不能视为任意网络环境的保证。

| 条件 | 耗时 |
|---|---:|
| C8287，原始 CAD 已缓存，首次二维转换 | 0.429 秒 |
| C8287，再次预览 | 0.250 秒 |
| C2053170，原始 CAD 已缓存，首次二维转换 | 0.224 秒 |
| C2053170，再次预览 | 0.187 秒 |
| C8287，完全没有 CAD 缓存，在线获取并准备二维 | 9.815 秒 |
| `stm32` 首次在线关键词查询 | 6.444 秒 |
| 同一关键词的后端缓存查询 | 0.001 秒 |

无缓存 C8287 的 9.815 秒中，9.611 秒用于获取供应方 CAD。首次联网耗时仍取决于上游接口。此前记录的 19.935 秒预览包含 STEP 下载；两次网络条件不同，不据此宣称固定提速倍数。

原生 Capture CEF 流程已完成 C8287 搜索、二维预览、缓存预览、按需三维，以及 C2053170 搜索和完整资源导入。该次二维预览回传约 0.5–0.9 秒，测试回调另包含 150 毫秒采样延迟。实际 8 MB STEP 在外部服务不可用时成功回退本地渲染，源 STEP 的 SHA-256 保持不变。

正式安装包已经部署，并在运行中的 Capture 内热加载自带 Python 运行时再次完成同一流程。安装版的二维预览回传约 0.35–0.65 秒（已有原始 CAD/准备缓存，包含 150 毫秒测试回调延迟）；整个七步测试约 9 秒。这不是首次联网下载性能。

## 验证范围

- Python：262 项中 259 通过、3 项平台或安装器显式启用项跳过；面板：36 项通过；更新服务器：14 项中 13 通过、1 项显式启用项跳过。
- Windows 安装器：独立 17.2/17.4 单版本安装与修复、空选择拒绝、0.47.0 → 0.48.0 升级、错误所有者拒绝及恢复、卸载保留库和工程测试通过。这些是假 Cadence 根目录的安装生命周期测试，不代表 17.2 原生运行。
- Capture 17.4：原生封装查找由 `Default` 变为正确 DRA 路径；真实 CEF 搜索、预览与资源导入成功。
- Allegro 17.4：使用实际用户环境，按文件名解析 DRA、PSM、PAD、STEP 成功；独立 DRA 副本读回 20 个引脚及原始 STEP 关联，源文件哈希未变。
- 后台进程：实际搜索/预览/导入 worker 的初始、结束及每 10 毫秒采样的控制台句柄均为 0。此前黑色闪窗的具体进程尚未完整捕获；这些记录不等同于逐帧证明整个桌面从未闪窗。
- 界面截图及鼠标通道不稳定，因此使用 Cadence 原生接口和 CEF 回传验证，没有将脚本测试写成鼠标人工验收。

不支持 CEF 的旧主机仍使用 Tk 备用窗口；该窗口预览会等待 STEP，未应用本次面板分阶段交互。

本机未安装 Cadence 17.2，17.2 仅做兼容及安装流程测试。补充的 PCB 中 PSM 实际放置测试在当时未完成。**2026-11-12 更正**：后续确认默认启动选择的产品不合适，显式使用官方 `-product OrCAD_PCB_Designer` 后可以正常启动并完成放置；此前概括为“PCB 许可证不可用”不准确。新证据和封装名大小写修复见 [0.49.0](v0.49.0.md)。此版本不重新声明全部 478 分类均已完成实机复验。

## 安装与更新

下载 [GitHub Release](https://github.com/BH4ME/cadence-component-forge/releases/tag/v0.48.0) 中的 `JLC2Cadence-0.48.0-Setup.exe`，选择 Cadence 和元件库目录。安装包包含运行时，不需要另装 Python 或 Node.js。`SHA256SUMS.txt` 提供文件完整性校验；这不是发行者代码签名。

升级不会自动关闭 Capture。常规安装后，保存工作并重新启动 Capture；从 `JLC/LCSC → Search Components...` 打开面板。开发版迁移会拒绝覆盖其他所有者的初始化文件，需备份并移除已确认属于本扩展的旧注册。

发布包仍未配置生产在线更新站点及签名公钥。GitHub Release 可供手动下载安装，“未配置在线更新服务器”仍表示尚未启用应用内更新。
