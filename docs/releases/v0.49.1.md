# v0.49.1 — Capture 首次建库后的放置修复

预发布验证记录：2026-11-12，Windows x64，MIT。**最终安装包已在本机安装，并通过重启后的 Capture 17.4 S039 生产插件验收。保持预发布，版本资产见 [v0.49.1 Release](https://github.com/BH4ME/cadence-component-forge/releases/tag/v0.49.1)。**

首次生成 OLB 后立即放置元件时，Capture 可能原生崩溃。修复在放置前使用 Cadence 官方 `DboLib_sGetNormalizedName` 归一化库路径，再调用原有 `PlaceNew`。本次产品改动不调整原始符号编号属性、几何、封装尺寸或 STEP。

四组对照显示：原路径在原编号属性和实验编号属性下均崩溃；官方归一路径在两种属性下均成功完成冷建并启动交互放置。原始数据组随后通过官方 API 提交、保存和独立读回，确认 1 个实例、20 个引脚和正确封装属性。另一组在后续 repair OLB 放置中由用户鼠标落点，保存及独立读回通过。两种提交方式分开计数，没有把 API 提交视为鼠标验收。

最终安装包 `0.49.1-94bc97f4592d` 的 setup 退出码为 0；744 个安装清单文件及 65 个应用源文件核对一致。配置只更新运行时 Python 路径，元件库位置和原工程 4 个文件保持不变。全新 Capture 进程使用正式插件、无 QA 函数覆盖，首次原生 OLB 构建与生产 `PlaceNew` 返回成功；API 提交保存后独立读回为 1 个实例、20 引脚、位号 `U?`，封装属性与准备结果一致。12 项生成资源前后哈希一致。该 API 本轮没有显式标注，不声称自动编号或新增鼠标验收。
