# v0.49.0 — Native placement verification and library integrity

发布日期：2026-11-12。Windows x64，MIT 开源。**预发布：原生批处理稳定性仍有未解决项，不代表正式上架验收通过。**

## 放置问题的实际原因

本机手动运行 PCB 正常，而此前默认脚本启动失败。对比同一空白测试板，默认启动和旧的 `-pcb` 参数失败，显式使用官方 `-product OrCAD_PCB_Designer` 后成功；实际运行产品为 OrCAD PCB Designer Professional 17.4 S039。此前“PCB 许可证不可用”的说法不准确，已经更正历史说明。产品选择仍应以用户安装中正常可用的产品为准，不自动尝试替代产品。

导出的封装名称与 Capture `PCB Footprint` 现在统一为实际 PSM 的小写名称。初次对照曾怀疑大小写导致放置失败，但进一步强制大写调用也成功，因此不将大小写认定为崩溃根因。规范化只改变目标标识，原始符号、焊盘尺寸、坐标及 STEP 不变。

## 修复

- **完整资源缓存**：索引损坏、文件缺失和非空但内容被改动的 XML、IR、STEP、DRA、PSM、PAD 都会被检测。重建前保留被修改文件的字节，备份位置在库目录 `.modified_assets`。
- **原生 OLB 缓存**：记录输入 XML 和输出 OLB 的字节数及 CRC32，检测损坏及输入变化。修复另存新 OLB，保留原文件，实际放置使用新路径。该校验用于检测文件变化，不是发行者数字签名。
- **焊盘覆盖**：同规格的原生 PAD 可能因构建内部数据不同而具有不同字节。现在按元件分配独立名称，避免一个元件的导入覆盖另一个元件的已校验焊盘；尺寸和孔径不变。
- **大型三维预览**：仅对实测超过 6 MiB 的预览记住结果，绑定原始 STEP 哈希、转换器/渲染器版本及大小上限。后续不重复启动转换；网络或暂时性故障仍会重试。独立受控测试从重复约 8.16 秒降到 0.0046 秒（缓存检查函数，不含完整界面），原始 STEP 不变。
- **产品选择与验收**：新增 [独立 PCB 放置验收工具](../../tools/acceptance/README.md)，要求明确产品名称并使用新输出目录。STEP 映射交互脚本增加可选 `-Product`，默认自动封装构建流程保持原有方式。

历史 478 个末级分类中，本轮可读取原始缓存的有 392 个；其中 292 个通过解析和基础校验，100 个明确拒绝，另 86 个没有原始缓存，未复验。对 8 个“基础解析通过、实际准备曾拒绝”的样本补跑后仍明确拒绝。这个离线检查不代表 292 个都成功生成，更不代表 478 类全部通过实机测试。

## 最终回归与未解决项

- 自动回归：Python **301 项，298 通过、3 跳过**；面板 **36 通过**；更新服务 **14 项，13 通过、1 跳过**。跳过项属于平台/显式启用安装流程，未把跳过计入通过。
- 最终安装包已执行独立 17.2/17.4 安装与修复、空选择拒绝、卸载保留用户库的测试；这是使用假 Cadence 根目录的安装器测试。实际本机 0.48.0 → 0.49.0 升级成功，保留之前版本及配置。
- 真实 Capture 内，OLB 首次转换、缓存复用、损坏检测、新路径修复以及独立 Dbo 重开成功。2026-11-12 补验安装版 0.49.0：三个空白工程和一个已有同名符号的工程，**4 轮均完成真实 CEF 搜索、预览、`PlaceNew` 返回、官方 `PlacePart` 提交、保存和独立 Dbo 读回**。已有工程保留 U1/U2/U3，新增 U4 的 20 个引脚及封装属性正确。四轮在同一 Capture 会话中使用热缓存，从搜索开始到放置响应累计 1.233–1.307 秒，不能代表联网冷启动性能。[补验报告](../qa/v0.49.0-capture-retest.md)。
- 补验移除了测试用 execution trace，未改变产品代码。此前带跟踪的空白工程出现过 Capture 原生崩溃，仍保留失败记录；成功复测不能单独证明跟踪就是崩溃根因。另已确认测试回调漏接 Cadence 追加的 hostedClientId 参数并修正测试脚本。自动截图仍超时，鼠标点击落点验收尚未完成。
- 最终 PCB 原生重复测试 **10 轮中 8 成功、2 失败**：一次 FPC 放置返回 nil 并发生 `0xC0000005`；一次已放置和保存，但批处理等待完成或输出结束超过 90 秒。后一轮 journal 已记录退出，测试未记录超时瞬间的进程状态，因此不能认定主进程卡死。相同库后续测试成功；现有日志未定位故障模块，失败不因重试成功而删除。[逐轮记录](../qa/v0.49.0-pcb-placement.json)。
- BGA 明确预览超限后，完整资源缓存调用为 **0.058 / 0.048 秒**，相比修复前 8.159 秒，不再重复启动原生构建或渲染器。该数字是后端函数时间，不能当作所有联网搜索的速度保证。

上述原生稳定性和鼠标交互验收未完成项应在正式面向客户上架前关闭。本次发布用于验证已修复的缓存、命名和速度问题；补验报告更新没有更换标签或安装包。

## 使用和上架范围

下载 [GitHub Release](https://github.com/BH4ME/cadence-component-forge/releases/tag/v0.49.0) 中的安装程序。包含运行时，无须另装 Python。升级保留用户配置、元件库和工程；常规安装后保存工作并重新启动 Capture。

本次验证环境为现有 Windows 电脑与 Cadence 17.4 S039。17.2 未安装，只有兼容代码和安装流程测试；尚未覆盖独立的干净客户环境及其他补丁版本。界面截图/鼠标通道不稳定，原生 API 证据不能替代全部人工交互验证。不能据此宣传“支持所有 Cadence 版本和所有立创元件”。

应用内更新的生产 HTTPS 地址和信任公钥仍未配置，当前发行通过 GitHub 手动下载安装。供应方原始 CAD/STEP 未随开源代码或安装包重新分发。
