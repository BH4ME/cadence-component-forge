# v0.49.0 原生进程监督补验

2026-11-12 的四轮预定后台测试全部通过，12 个原生阶段均正常退出，没有超时或强制终止。本轮未观测到测试 PID 的可见窗口；库内 1,335 个文件在测试前后的 SHA-256 清单完全一致。

本轮验证改进后的验收脚本及指定样本。此前一次 FPC 原生异常退出与一次批处理等待超时仍保留在[原验收记录](v0.49.0-pcb-placement.json)，不能据此宣称原生崩溃已经解决。

## 测试方式

- 环境：OrCAD PCB Designer Professional 17.4 S039，明确指定 `-product OrCAD_PCB_Designer`。
- 每次启动使用 `-nograph` 和 `CREATE_NO_WINDOW`，每轮创建独立输出目录，不操作用户 PCB。
- 固定执行 C9160 FPC 两轮和 C11255 通孔电阻两轮，没有自动重试或增加轮数。
- 每轮依次读取源 DRA 副本、在新 PCB 放置并保存、重新打开 PCB 回读。
- 各阶段以普通文件记录标准输出、标准错误，并记录启动 PID、时间、退出码、超时及终止状态。
- 每 50 ms 检查当前记录的原生 PID 是否拥有可见窗口；若观测到则停止测试。本轮未触发。

每轮均核对了针脚编号、padstack 名称和扣除 25 mm 平移后的针脚中心坐标，容差为 0.00005 mm。FPC 的最大中心坐标差为约 3.55×10⁻¹⁵ mm，通孔样本为 0；STEP 关联元数据完全一致。源 DRA、PSM 及整库文件内容均未改变。

## 诊断改进与结论范围

独立 Python 父子进程实验复现了旧方法的歧义：父进程已退出且返回码为 0，后代仍持有输出管道时，`communicate()` 仍可能超时。改用独立日志文件和针对启动 PID 的 `wait()` 后，同一实验能在后代尚未退出时正确记录父进程完成。

这项实验说明验收脚本需要区分进程结束与输出管道 EOF，不能证明它就是此前 Allegro 超时的实际原因。新脚本遇到真实超时、异常退出或缺少 PCB/回读文件仍判定失败，不重试、不掩盖。

四轮成功是有界补验结果，不是长期稳定性证明。此检查不覆盖完整图形几何、3D 实体配合、交互式 3D 显示或设计级 DRC；Cadence 17.2 尚无本机实测。

完整数值和阶段状态见[脱敏 JSON](v0.49.0-native-supervision.json)。复现方法见[验收脚本说明](../../tools/acceptance/README.md)。
