日期：2026-11-12。环境：Windows x64 / Capture 17.4 S039，一台现有电脑。元件：`C2053170 / STM32F031F6P7TR`，20 引脚。**官方 OLB 路径归一化修复已通过对照实验，以及最终安装包重启 Capture 后的生产插件验收。符号编号属性和几何保持原样，发行保持预发布。**

结构化结果和脱敏证据哈希见 [JSON](v0.49.1-capture-placement.json)。本报告接续 [v0.49.0 复测](v0.49.0-capture-retest.md)及[崩溃审计](v0.49.0-capture-crash-audit.md)，保留之前的失败记录。

## 对照条件

四组均使用独立空白工程，开始时原生 OLB 文件、OLB integrity 文件、页面实例和设计缓存 package 数量均为 0。这里的“冷建”指**首次生成原生 OLB**：供应商数据、转换 XML、IR、封装和 STEP 已在本地缓存。两个归一化成功组运行于同一 Capture 会话，不能计为两次宿主冷启动，也不代表首次联网下载。

面板通过真实 CEF 搜索 `C2053170`、点击结果、预览和放置，调用生产 `buildOlb`，随后调用 `PlaceNew`。没有使用 execution trace，也没有在外部提前构建 OLB。归一化实验只在 QA 会话中替换 `finish` 的 OLB 路径实参；仍使用原 `PlaceNew`、原符号名和第三参数 `0`，不修改 `lastImport`。已安装的 0.49.0 源文件未因此改动。

## 人工落点与 API 提交的边界

**alpha2 的冷建返回与人工落点是两次调用。** 首次冷建返回使用初始 `LIBRARY.OLB`；11:22:56 的鼠标验证使用后续完整性修复产生的 `LIBRARY.verified.…olb`。该次再次点击 Place 后，用户在画布落点，观察器记录 `human_mouse_observed`、U1、20 引脚、实例数 0 → 1。保存后独立 Dbo 重开确认 U1 / STM32F031F6P7TR / 20 引脚。不能把这次鼠标落点归入首次冷建调用。

**alpha0 的保存验证使用测试 API。** 首次冷建 `PlaceNew` 返回后，测试脚本结束交互放置，使用相同 OLB 的官方归一化路径调用 `PlacePart`，再显式 `SetReference U1` 并保存。独立读回确认实例数 1、U1、20 引脚和 `PCB Footprint=c2053170_tssop_20_l6_5_f2bd621e`。此项不是鼠标落点或自动位号分配验收。

## 保持原始数据

- alpha0 两组的 22 项复制资源与生产来源逐字节相同，包括符号 XML、供应商记录、IR、STEP、DRA、PSM 和 PAD。
- alpha2 两组只在完整构建 XML 中将 `alphabeticNumbering="0"` 的一个 ASCII 字节改为 `2`；文件仍为 206,568 字节。二维预览 XML 和其他 21 项资源不变，manifest 只调整路径和这一 XML 的校验值。
- 实际 OLB 原生读回证明 alpha0 的 device designator 为 `-1`，alpha2 为空；两者 20 个引脚的编号、名称、起点、热点、方向和电气类型逐项相同，边界框均为 `{-75 -51 75 60}`。源 XML 的完整 NormalView 和 PhysicalPart 结构也相同。
- 两组实际生成的 native import Tcl 在归一化测试目录后，仅 device-designator 赋值一行不同。OLB 只读检查前后 SHA-256 不变。`GetId` 返回 0 但状态失败，记录为不可用，不当作有效零 ID。

因此最终产品修复限定为**官方 OLB 路径归一化**，保留原编号属性、原几何和 STEP。使用 `DboLib_sGetNormalizedName`，不以自行转大写替代官方规则。官方依据为安装脚本 `capUnifiedSearch/tcl/OrHandlerUnifiedSearch.tcl:764–767` 的路径准备流程；本修复继续调用产品原有 `PlaceNew`，不借用该官方示例的其他放置 API 参数。
