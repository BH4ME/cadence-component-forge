# JLC/LCSC Cadence 扩展 Windows 使用说明

版本：0.48.0。安装程序包含 Python、转换依赖和界面资源，使用者不需要另装
Python、Node.js 或 Codex。Cadence Capture 和 Allegro 需要自行安装。

当前已发现并实测 Cadence 17.4；安装程序支持选择 17.2 和 17.4，
但本机没有找到 17.2，因此 17.2 的实际运行验收尚未完成。

## 安装与打开

1. 运行发布包中的 `JLC2Cadence-0.48.0-Setup.exe`。
2. 选择已安装的 Cadence 根目录，例如 `C:\Cadence\SPB_17.4`。
   程序检查实际可执行文件版本，不会将缺少的 17.2 自动替换成 17.4。
3. 选择元件库保存目录。安装程序不需要打开、修改或保存现有工程。
   Cadence 原生工具对过长路径可能有限制；如果安装根、状态目录、库目录和
   测试目录叠加后接近 Windows 路径上限，安装会安全失败并保留旧注册。
   建议使用较短路径，例如 `C:\JLC2Cadence`、`E:\JLC2Cadence\library`。
4. 安装后，在方便的时候保存自己的工作并重新启动 Capture。
   安装程序不会强行关闭 Capture；已经运行的会话继续使用原先加载的版本。
5. 在 Capture 的 `JLC/LCSC → Search Components...` 中搜索型号、关键词或 C 编号。
   支持 CEF 的环境使用内嵌浏览器；缺少所需浏览器接口时使用原生 Tk 搜索窗口。

支持 CEF 时，搜索页会使用 Capture 的 `orPrm::CreateControlBar`（`WDOCK_RIGHT`）固定到右侧
控制栏（不是 Windows 桌面任务栏）。如果右栏被 Capture 记忆成很窄的宽度，
页面会自适应重排，仍然留在右侧；重新点一次菜单即可重新显示。旧版的窄栏
会被切换成 MDI 标签页，升级后默认不再这样处理。确需旧行为时可在配置中设置
`use_mdi_fallback=true`。

搜索速度：关键词和分页结果会在元件库根目录的 `cache/catalog` 保存 5 分钟，
网络暂时不可用时可使用 1 小时内的旧结果；同一 Capture 会话还会直接复用最近的
页面结果。首次查询一个从未搜索过的关键词仍需访问立创服务器，网络响应时间无法由
插件完全消除。已完成元件的预览和资源也按内容指纹复用，不会每次点击都重新生成。
已经下载过的元件再次按 C 编号搜索时直接读取本地官方记录，不再重复访问网络；
首次关键词查询仍受立创服务器响应时间影响，后续相同查询会优先使用缓存。
CEF 内嵌面板点击元件先显示原始符号和封装的二维预览，STEP 下载与网格生成由 **加载 3D** 按钮按需触发。
二维预览也有独立缓存，重复选择无需等待三维生成；加载时可以切换元件，过期响应不会覆盖新选择。
Tk 备用窗口仍使用原有的完整 STEP 准备流程。
后台 worker 统一选择 `pythonw.exe`；缺少无窗口运行时时明确提示修复安装。
外部三维预览服务不可用时，程序回退到随安装包提供的本地 STEP 预览组件。

若检测到另一个安装目录或开发版留下的同名初始化文件，安装会明确报错。
不要直接覆盖未知文件。迁移应先备份已确认属于本扩展的初始化文件，并在失败时恢复。

## 下载、放置和文件

`Download Resources` 下载立创关联的原始符号、封装和 STEP，并转换成 Cadence 文件。
`Place Schematic` 同时把符号库加入 Capture，进入交互放置；先激活目标原理图页面。
程序会核对目标工程与页面，目标已关闭时拒绝继续放置。

同一元件库根目录按版本分成 `cadence-17.2` 和 `cadence-17.4`，每个子目录内包含：

| 路径或文件 | 用途 |
|---|---|
| `parts/C编号/版本标识/capture/*.olb` | Capture 原理图符号库 |
| `allegro/symbols/*.dra` | Allegro 可编辑封装源文件 |
| `allegro/symbols/*.psm` | Allegro 放置使用的编译封装 |
| `allegro/padstacks/*.pad` | 焊盘文件 |
| `3d/*.step` | 供应方原始三维模型 |
| `allegro_paths.env` | Allegro 的 psmpath、padpath、steppath 配置参考 |
| `parts/.../reports/source_provenance.json` | 源记录、转换来源及原始 STEP 哈希 |

0.48.0 会在打开插件及导入完成后登记 Capture 封装路径，并在资源导入完成时登记 Allegro 的
`psmpath`、`padpath`、`steppath`，保留已有路径并备份被修改的环境文件。已运行的 Allegro
需要重新启动以读取新设置；权限不足等登记失败会明确写入警告。
Capture 的 `PCB Footprint` 属性填写生成的封装名，不带 `.psm` 后缀。

Capture 编辑的是原理图符号和 `PCB Footprint` 关联属性；实际焊盘、丝印等
PCB 封装几何应在 Allegro 中打开 `.dra` 编辑，再重新生成 `.psm`。
建议复制库文件后编辑，避免把个人修改与下一次导入混在一起。

## 源数据缺失和转换限制

- 确认找不到供应方 CAD 库时：**没有 CAD 文件：未找到该元器件的立创原始 CAD 库，无法导入。**
- 已确认包含当前无法忠实转换的异形结构时：**由于是异形结构，当前无法生成。**
- 仅缺少 STEP 时，会保留能够转换的符号和封装，并明确标记 STEP 缺失。
- 网络错误、服务故障、原始字段缺失、字体或目标精度问题会保留其实际原因，
  不会一律显示为“没有 CAD”或“异形”。

程序不补画缺失符号、封装或三维模型，不擅自修改尺寸。
位号前缀只采用原始器件属性中能够核实的类型，例如 `R?` 转换成 Allegro 的 `R*`。
无法核实的数据会被报告。异形限制指当前转换能力，不代表原器件本身不可用。

STEP 预览只对原始文件进行三角网格显示和必要的单位/坐标转换，原始 STEP 保持不变。
预览失败或模型超过显示大小限制，不代表已经下载的 STEP 文件不存在。

## JLC/LCSC 菜单中的两项都变灰

0.47.0 的菜单启用回调错误地返回了数字 `1`。Capture 的菜单 Update 回调要求
返回 `true` 或 `false`，因此“Search Components...”和“Check for Updates...”会一起禁用。
0.48.0 安装包已包含修复，将菜单 Update 回调与动作处理的前置判断分开。

已经打开的 Capture 会继续使用旧回调。更新插件源码后，保存工作并重启 Capture 即可加载修复。
也可以在当前会话选择 **View → Command Window**，输入下面一行并按 Enter：

```tcl
proc ::JLC2Capture::menuEnabled {args} { return true }; RefreshMenu
```

这条临时修复只更新菜单回调，不修改工程或元件库；使用旧安装包时下次启动仍需重新执行。
菜单恢复后选择 **JLC/LCSC → Search Components...** 打开搜索面板。

## 在线升级

Capture 中打开 `JLC/LCSC → Check for Updates...`，或点击内嵌页面的更新按钮。
先检查版本和说明，再点击“下载并安装”。下载时验证发布清单签名、包大小及 SHA-256，
版本变化时要求重新检查；不会静默切换到未经用户查看的版本。

安装完成后重新启动 Capture 生效。界面显示“安装程序已启动”只表示启动成功，
不表示所有安装步骤已完成；安装结果以安装程序和安装日志为准。
正在导入元件时不启动更新安装。旧版本目录与已有库文件会保留。

管理员需要在持久化 `config.json` 配置：

```json
{
  "update_manifest_url": "https://你的更新域名/manifest.json"
}
```

上面的域名是占位示例，不是已经部署的服务。发布包默认未配置生产服务器和信任公钥，
此时检查更新会明确提示未配置。生产签名私钥保存在发布者电脑，不能放入安装包或公开目录。
安装版把信任公钥固定在安装目录的 `installer/update-public-keys.json`，
不会接受普通配置把信任公钥重定向到其他文件。默认下载缓存位于当前用户
`%LOCALAPPDATA%/JLC2Cadence/updates`，也可配置 `update_cache_dir`。
服务部署和签名工具分别见 `tools/update_server/README.md`、`packaging/release/README.md`。
本地验收允许显式开启 loopback HTTP；正式更新使用 HTTPS。

## 卸载

在 Windows“已安装的应用”中卸载 JLC2Cadence，或运行安装目录中的卸载程序。
卸载删除本安装拥有的插件注册和程序文件，保留元件库、配置及工程文件。
已经打开的 Capture 可能仍显示旧菜单，重新启动后消失。
